## 3. 데모 가능 여부 판정표 (세 가지 필수 조건)

데모의 정의: (a) 웹 채팅 풀플로우 실동작 + (b) OCI 배포 URL에서 확인 + (c) 카카오 공유가 실제 도메인에서 동작.

| 조건 | 판정 | 근거 (실측 vs 미확인 분리) |
|---|---|---|
| (a) 요구사항→견적→시안→코드생성→배포 풀플로우 | **부분완료** | ✅ 백엔드 파이프라인: OCI curl로 입장→승인→견적(A/B/C+추천B)→진행→시안 200→폴링 DONE→배포 200+Hermes 실콘텐츠까지 오늘 통과 (OCI 검증 §2~§8). ✅ 1:1 `/chat` 로컬 e2e: STATUS 기록. ⬜ **OCI에서의 브라우저 클릭 흐름(1:1 index + room 3브라우저)은 미검증** — curl 통과와 브라우저 통과는 다른 것이다 |
| (b) 로컬이 아닌 OCI URL에서 확인 가능 | **완료 (백엔드 한정)** | ✅ `GET /health` 200, `/design/<id>` 200(2398B), `/site/<id>/` 200(카페 예약 실콘텐츠) 오늘 실측. ✅ `/room.html` → 200 (OCI 검증 "관찰 3"에서 `GET /room.html` 200 실측). 단, 브라우저 렌더·폴링 UI까지 본 것은 아님 |
| (c) 카카오톡 공유가 실제 도메인에서 동작 | **부분완료** | ✅ index.html 배포 링크 공유: 실사용자 클릭→팝업→실제 카톡 수신 검증済 (KAKAO 계획 §0 인용, ENVIRONMENT §3-6, `c510f2b`). ⬜ 시안 링크 공유: 로컬 검증만 (STATUS). ❌ **room.html 초대 공유의 OCI 정식 판정(C-1): 미실행.** `file://` 4019 건은 미확정 가설 상태 |

**종합: 3개 중 1개 완료 + 2개 부분완료 → "부분가능".** 오늘 경영진을 부르면 (a)의 브라우저 대목과 (c)의 room 대목에서 막힐 가능성이 높다.

### room 기능의 데모 포함 여부 판정

- room은 원래 요구사항에 없던 **이번 세션 신규 기능**이다. 잘되면 가점이지만, 깨지면 본편(1:1)까지 신뢰를 잃는다.
- 현재 상태: **백엔드는 OCI 통과, 프론트는 로컬만, 카카오 초대는 미검증.** 즉 "API는 된다, 사람이 쓰는 모양으로는 아직 못 보여준다".
- **판정: 본편에서 제외, 보너스로만 언급.** 권장 멘트: "다인원 room 백엔드는 오늘 OCI에서 끝까지 통과했습니다. 브라우저·카카오 초대는 검증 중이라 오늘은 1:1 흐름만 시연합니다."
- 포함 승격 조건 (3개 전부): ① OCI 브라우저에서 2개 창 입장→투표→견적→시안→DONE 실측 ② OCI 도메인에서 카카오 초대 실제 수신 + `?room=` 입장 ③ 리허설에서 90초 대기 포함 통시간 측정. **하나라도 빠지면 포함하지 마라.**

## 5. 오늘 당장 봐야 할 경우의 "최소 안전 데모 시나리오" (축소판)

원칙: **검증된 것만, 미리 데워둔 것, 클릭 수 최소.** 소요 5~7분 (90초 대기 포함).

1. **사전 준비 (청중 입장 전):** OCI `warmup.sh` 통과 확인. 발표 시간대에는 `deploy.sh` 실행 금지 (R5). 브라우저 북마크: `http://144.24.91.250.sslip.io:8643/` (index) + `/room.html`은 열지 않음. 발표용 입력은 **"카페 예약 웹사이트" 고정** — 오늘 OCI에서 Hermes 실콘텐츠까지 확인된 유일한 입력이다 (OCI 검증 §8).
2. **시연 ① 채팅→견적 (1:1만):** index에서 "카페 예약 웹사이트 만들고 싶어요" → AWAIT_APPROVAL 확인 → "승인" → A/B/C+추천B 견적까지. RAG 매칭형이 아닌 범용 템플릿이 나와도 당황하지 말고 "신규 유형이라 기본안으로 잡혔습니다" 한 줄 멘트 (R2 대비).
3. **시연 ② 시안:** `/design/<id>` 미리보기 1장만 보여준다. "여러 종" 언급 금지 (R6). 스크린샷 로딩은 미리 열어 캐시해 둔다.
4. **시연 ③ 코드생성 대기 처리:** "진행"을 누른 뒤 **대기 시간을 예고한다** ("코드생성은 최대 90초, 오늘 실측은 약 24초였습니다"). 대기 중에는 아키텍처 1장(파이프라인 그림)으로 말을 잇는다 (R1 대비). 절대 대기 중에 새로고침·재전송 금지.
5. **시연 ④ 배포 + 카카오:** `/site/<id>/` 접속 1회 + **카카오 공유는 index 배포 링크만**, 그것도 "어제 실사용자 수신까지 확인된 버튼입니다. 오늘은 팝업까지만 보여드립니다"로 끊는다. 실제 전송 클릭은 리스크이므로 생략 권장. **room 초대 버튼은 누르지 않는다** (R3).
6. **말하지 말 것:** room 브라우저 시연, 시안 카카오 공유, ⑱ 승인 ("없다"고만 묻기 전에는 먼저 꺼내지 않되, 물으면 R4대로 정직 답변).
