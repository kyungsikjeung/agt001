# 음성 요구사항 대화 요구사항 (VOICE_QA_REQUIREMENTS)

> 작성 2026-09-27, Claude(PM). 목적: 요구사항 엔진이 **질문을 소리로 읽어 주고, 사장님이 말로 답하면 칸이 채워지는** 흐름을 지금 있는 것 위에 얹기 위한 요구사항과 병행 작업 나누기.
> 바탕: [VOICE_INPUT_PLAN](VOICE_INPUT_PLAN.md)(부록 NVIDIA 실측), [FLOWDOC](FLOWDOC.md) §1 음성 행, `static/voice.js`, `app/services/stt.py`·`tts.py`, `app/services/prd_engine.py`, T3 평가 r5(21/36).

## 0. 결론 먼저

- **새로 만들 것은 "음성용 질문 문장 + 말로 한 답 알아듣기 + 중요한 값 복창 확인" 3가지가 핵심이다.** 녹음·전사·합성·무전기 모드(누르고 말하기·자동 전송·답장 자동 읽기)는 이미 운영 중이다.
- 엔진(`prd_engine.py`)은 지금 T3 수정 작업(OpenCode)이 쓰고 있으므로, 음성 쪽은 **새 파일 `app/services/voice_turn.py`** 에 모아 엔진을 감싸는 방식으로 병행한다. 엔진 안쪽 수정은 T3 작업이 끝난 뒤 1건(V-4)만 한다.
- 합격선: 음성 전용 T3(같은 36개 시나리오를 합성→전사 잡음을 넣어 돌림)에서 **텍스트 T3 대비 통과율 하락 5%p 이내, 전화·가격 지어냄 0건, 턴당 응답 4초 이내**.

## 3. 기능 요구사항 (FR)

## 8. 2단계: 전화로 요구사항 대화 (콜봇) — 2026-09-27 추가

> 사용자 결정(9/27): **콜봇은 1:1 채팅방에서만** 쓴다. 여러 명이 있는 방에서는 쓸 수 없다. 기술 검증은 **Twilio 미국 번호(체험 계정)**로 빠르게 한다.

### 8.1 왜 1:1만인가

전화는 한 사람의 목소리만 받는다. 공유방에서 전화로 답하면 ① 다른 참여자는 대화에 끼어들 수 없고 ② 방장 확인(D24)·의견 충돌 투표 같은 공유방 규칙을 전화로는 지킬 수 없으며 ③ 전화 중 다른 사람이 채팅으로 같은 칸을 바꾸면 두 입력이 부딪힌다. 그래서 **사람이 나 혼자인 방(참여자 1명 = 방장)**에서만 켠다.

### 8.2 화면 노출 규칙

`GET /room/{id}/messages`의 `members`로 판단한다(이미 내려옴).

| 방 상태 | "전화로 답하기" 버튼 | 사용자에게 보이는 말 |
|---|---|---|
| 참여자 1명(나 = 방장), 요구사항 대화 중 | **보임, 누를 수 있음** | "전화로 답하기 — AI가 전화로 질문하고, 답하신 내용은 이 채팅에 그대로 남아요" |
| 참여자 2명 이상 | **보이지만 흐리게, 누를 수 없음** | 누르면 한 줄: "전화 답하기는 혼자 쓰는 방에서만 돼요. 여러 분이 함께인 방에서는 채팅으로 답해 주세요" |
| 참여자 1명이지만 내가 방장이 아님(방장이 나감 등) | 숨김 | — |
| 요구사항 대화가 끝남(시안 단계 이후) | 숨김 | — |
| 전화 중 | 버튼 자리에 "통화 중 · 끊기" | 채팅창 위에 "전화로 대화 중이에요. 채팅으로 입력하면 전화가 끝나요" |
| 전화 중 두 번째 사람이 들어옴 | — | 전화에서 "다른 분이 들어오셔서 전화를 마칠게요. 채팅에서 이어 주세요" 후 끊고, 채팅에 같은 안내 |

- 버튼 위치: 더보기 시트의 무전기·읽어주기·손 안 쓰는 모드 스위치 옆. 1:1이 아닐 때 **숨기지 않고 흐리게** 두는 이유: 기능이 있다는 것은 알리고, 왜 안 되는지 한 줄로 설명하기 위해.
- 서버도 같은 규칙을 강제한다: 전화 시작 API는 참여자 1명·방장·요구사항 대화 중일 때만 허용(403). 전화 중 매 턴 참여자 수를 다시 보고 2명 이상이면 끊는다. 화면만 믿지 않는다.
- 전화 답은 채팅 메시지로도 남는다(누가 무엇을 말했는지 기록, 요약 카드는 화면에서 최종 확인 D22).

### 8.3 기술 검증 (PoC) — Twilio 미국 번호

목표: "AI가 전화로 묻고 → 사장님 답 → 엔진이 다음 질문"이 **한국어로 실시간** 되는지. 잴 것: 한국어 받아쓰기 정확도, 말 끝 감지, 말 끝 → 다음 질문 소리까지 조용한 시간, 끼어들기, 키패드 선택.

```mermaid
sequenceDiagram
    participant O as 사장님 휴대폰
    participant T as Twilio (ConversationRelay)
    participant S as 우리 서버
    participant E as 요구사항 엔진
    S->>T: 1. 전화 걸기 요청 (1:1 방만, 시험 번호만)
    T->>O: 2. 전화 걸기 (미국 번호, 체험 안내 멘트)
    T->>S: 3. 통화 연결 알림 + 서명 확인
    S-->>T: 4. ConversationRelay 연결 지시 (한국어)
    T->>S: 5. 실시간 연결 (WebSocket)
    S->>E: 6. 다음 질문
    S-->>T: 7. 읽을 질문 글자
    T->>O: 8. 질문 소리
    O->>T: 9. 말로 답 / 키패드
    T->>S: 10. 받아쓴 글자
    S->>E: 11. 답 넣기 (채팅에도 기록)
    E-->>S: 12. 다음 질문 또는 끝
```

| 번호 | 설명 |
|---|---|
| 1 | 방장이 "전화로 답하기"를 누르면 서버가 Twilio REST로 발신 요청. PoC는 **허용 목록(환경변수)의 번호로만** 건다 — 아무 번호로나 걸리는 남용 방지 |
| 2 | 체험 계정은 인증한 번호(최대 5개)에만, 통화 10분까지, 시작 때 체험 안내 멘트가 나온다 |
| 3~4 | Twilio가 우리 주소를 부르면 **Twilio 서명을 확인**한 뒤 `<Connect><ConversationRelay language="ko-KR" …>`로 답한다. 방 정보는 짧게 사는 서명 토큰으로 넘긴다 |
| 5 | ConversationRelay가 받아쓰기·합성·말 끝 감지·끼어들기·키패드를 맡고, 우리는 WebSocket으로 글자만 주고받는다 |
| 6~8 | 엔진 질문을 FR-1 읽기용 문장으로 바꿔 보낸다 |
| 9~11 | 받은 글자는 채팅 답과 똑같이 엔진 `turn()`에 넣는다(FR-2 말로 고르기·FR-6 다시요 그대로). 키패드 숫자는 선택지 번호로 |
| 12 | 끝나면 "요약은 채팅에 남겼어요"라고 말하고 끊는다. 매 턴 참여자 수를 확인해 2명 이상이면 끊는다 |

**PoC 합격선:** 한국어 5턴 연속 진행, 말 끝 → 다음 질문 소리 3초 이내(중앙값), 선택지 키패드 100%, 전화번호 복창 1회로 확정.
**잘 안 되면:** 한국어 인식이 약하면 받아쓰기 제공자(Google ↔ Deepgram)를 바꿔 보고, 조용한 시간이 길면 추출 모델을 한도 없는 빠른 모델로. 그래도 안 되면 B안(실시간 음성 모델 + 엔진 도구 호출).

### 8.4 운영 단계 (PoC 통과 뒤)

- 한국 번호: Twilio는 한국 번호를 주지 않는다(개인·리셀러 모두). 미국 번호로 걸면 "국제전화"로 떠서 사장님이 잘 안 받는다 → 운영은 **국내 070**(ClawOps 체험 → 안정성 확인, 부족하면 KT·LG U+ SIP)으로. 이때 ConversationRelay를 못 쓰므로 구조가 B(실시간 모델 SIP) 또는 C(음성 중계 + 우리 받아쓰기·합성)로 바뀐다.
- 녹음·받아쓰기 고지와 동의(통화 시작 멘트), 사장님이 요청했을 때만 발신, 발신번호 사전 등록 규정 준수.
- 비용: 통화료 한국 휴대폰 약 $0.05/분 + 음성 처리. 5분 통화 약 $0.3~1.
