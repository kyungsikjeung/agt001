# 베타 전 운영 절차 (10/1 배포 뒤 한 번, 운영자용)

> 대표 피드백 10/1(D58) 기능이 운영에 나갔다(PR #3, `059668a`). 이미 공개된 가게에 새 모양을 반영하고, 메뉴 태그 사진 창고를 미리 채운다.
> 서버 명령은 모두 서버(`ssh ubuntu@144.24.91.250`)의 `~/agt001`에서 실행한다. 스크립트는 backend 컨테이너 안에서 돌린다(COMMERCE_RUNBOOK과 같은 방식):
> `sudo docker compose exec -T backend sh -c 'PYTHONPATH=/app python scripts/<스크립트>.py [인자]'`
> 두 스크립트 모두 **기본은 미리 보기**라 인자 없이 돌리면 아무것도 바꾸지 않는다.

## 1. 공개된 가게 한꺼번에 다시 공개 (`scripts/republish_all.py`)

| 순서 | 명령(스크립트 이름과 인자만) | 하는 일 |
|---|---|---|
| 1 | `republish_all.py` | 미리 보기. 공개된 가게 키와 "가게 행 없음"·"좌표 없음" 표시, 합계 |
| 2 | `republish_all.py --apply --only <가게 키>` | 한 곳만 먼저 해 보고 공개 사이트를 연다(지도·"채팅하기"·공지) |
| 3 | `republish_all.py --apply --geo` | 전부: 빠진 가게 행 채우기 + 새 모양으로 다시 공개 + 주소가 딱 하나로 찾아지는 가게만 지도 좌표 채우기 |

- **가게 행 없음**: 10/1 전까지 공개 때 가게 행(shops)이 안 생기던 버그 때문이다. 이 행이 없으면 손님 채팅·예약이 열리지 않는다. `--apply`가 채운다.
- **`--geo`가 하지 않는 것**: 주소를 못 찾거나 여러 개로 찾으면 그 가게는 그대로 둔다. 공개된 주소를 빈칸이나 임시 주소로 바꾸지 않는다. 그런 가게는 사장님이 빌더·편집기의 "주소 검색"으로 고르면 된다.
- 출력은 가게 키만 나온다(이름·전화·주소 없음). 실패가 있으면 종료 코드 1이고 그 가게 키와 이유가 한 줄씩 나온다.
- 되돌리기: 다시 공개는 공개 파일만 새로 쓴다. 문제가 있으면 배포 스냅샷(`~/agt001-releases/`)으로 `scripts/rollback.sh`.

## 2. 메뉴 태그 사진 창고 미리 채우기 (`scripts/prefill_art_lib.py`)

| 순서 | 명령 | 하는 일 |
|---|---|---|
| 1 | `prefill_art_lib.py` | 미리 보기: 낱말표 태그 수, 이미 있는 수, 없는 태그 목록, 예상 비용 |
| 2 | `prefill_art_lib.py --apply --limit 5` | 5장만 먼저 만들고 `/art-lib/<태그>.webp`를 열어 본다(사람·글자·간판 없음 확인) |
| 3 | `prefill_art_lib.py --apply` | 나머지 전부(약 113장, 장당 $0.039, 합계 약 $4.4) |

- 만든 사진은 서버 `generated/art-lib/`에 쌓이고, 모든 가게가 같은 태그를 다시 쓴다. 로컬에서 만든 사진은 운영으로 옮겨지지 않는다.
- 미리 채우지 않아도 사장님이 메뉴를 넣으면 그 메뉴 사진은 뒤에서 만들어진다(20초쯤). 미리 채우면 첫 화면부터 바로 보인다.
- 하루 상한은 `.env`의 `ART_LIB_DAILY_CAP`(기본 0 = 없음, D58 ③)이다. 비용은 D39 월 상한 안에서 매일 확인한다.
