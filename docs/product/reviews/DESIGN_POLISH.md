# 시안 다듬기 기록 (작업 P2)

작성: OpenCode / 일자: 2026-09-26
요청: "텍스트만 나와서 밋밋하다, 예쁘게"
소유 파일: `templates/site.css`, `templates/sections/*.mustache`(기존 다듬기 + 2종 새로),
`templates/README.md`, 이 문서.
`app/services/site_render.py`는 손대지 않았다(다른 작업 소유).

## 1. 바꾼 것 (CSS·표시 구조만, 스크립트 없음)

- 첫 화면(hero)
  - 큰 제목 글씨 크기 대비: `.s-title` 휴대폰 24px → 32px, 760px 이상 32px → 40px.
    SPEC §1.2(24/32px)보다 키웠는데, P2 지시가 크기 대비를 직접 요구해서다.
    본문 16px은 그대로라 제목·본문 대비가 2배가 된다.
  - 사진 위 글자 가독성: 겹침형 덮개를 `transparent → .45` 2단계에서
    `.12 → .45 → .68` 3단계로. SPEC 고정값 계열(검은 스크림 + 흰 글자) 안에서만 손봤다.
    겹침형 제목에 `text-shadow`를 더했다.
  - 버튼: 첫 화면 CTA만 키움(최소 높이 52px, 글자 17px) + 그림자.
  - 휴대폰 첫 화면 높이: 전 hero 변형에 `min-height: 70vh` + `70svh`(구형 대체).
    390x844 캡처에서 첫 화면이 약 590px(약 70%) 나온다. PC 겹침형은 440px 그대로.
- 섹션 사이 리듬
  - 첫 화면을 제외한 짝수 번째 섹션에 `--ground-soft` 띠를 번갈아 깐다.
    표시 구조를 바꾸지 않고 CSS만으로 전체 너비 띠를 만든다(그림자+잘라내기 기법).
    숫자 강조 띠(`s-stats--band`, 자체 주색 바탕)는 리듬 띠 대상에서 뺐다.
  - 제목 장식: 전 부품 공통 왼쪽 색 막대를 없애고 아래 짧은 강조선(`::after`)으로.
    모서리 토큰(`--radius-btn`)을 써서 알약형(soft·round)은 둥글게, 각진형(sharp)은
    네모로 바뀐다. 부품마다 다르게: 상품 56px 길게, 사진첩 두 색 이어짐,
    후기 둥근 점. 3안(VARIANTS)이 바꾸는 게 밀도·모서리·글꼴이라 모서리 토큰에 묶었다.
  - 카드: 바탕을 `var(--card)`(없으면 흰색)로, 그림자를 구분선 색(`--line`)으로 번지게.
    팔레트마다 그림자 색이 따라간다. 모서리는 기존 `var(--radius-card)` 그대로.
  - 작은 꼬리표(`s-kicker`): 알약형 배지로. 겹침형 위에서는 반투명 검정 배지로 읽힌다.
- 부드럽게 나타나기
  - `@keyframes s-rise` 1개. 첫 화면은 읽자마자, 나머지는 `animation-timeline: view()`
    대응 브라우저에서만 스크롤에 따라 나타난다. 모르는 곳은 가만히 보인다.
  - `prefers-reduced-motion`에서는 전부 끈다. 기존 전체 선택자(`*`) 규칙은
    특이성이 낮아 섹션 나타내기를 끄지 못해서(실측 확인)
    `section[class^="s-"]:not(.s-hero), .s-hero { animation: none; }`을 명시했다.
    움직임을 줄인 옛 브라우저에서도 전과 같이 보인다.
  - 인쇄(`@media print`)에서도 나타내기를 끈다. 고정 캡처·인쇄물이 빈칸이 되지 않게.
- 공개 사이트(`body.is-public`) 규칙은 그대로 둔다. 끝부분 4줄 손대지 않음.
  공개 렌더로 확인: 빈칸 숨김·빈 부품 제외·빈 가격 "가격 문의" 그대로 나온다.

## 2. 새 부품 2종 (표시 구조 + 변수 계약, 렌더러 미연결)

- `features--icons.mustache`: 특징 3칸(인라인 SVG 아이콘 6종 중 선택 + 제목 + 한 줄).
  아이콘 6종: `star`·`pin`·`clock`·`phone`·`leaf`·`heart`.
  전부 획 아이콘(`stroke="currentColor"`), 글자 없음, 외부 호출 없음.
  SPEC 클래스 규칙(`s-<type> s-<type>--<variant>`)을 따랐다.
- `stats--band.mustache`: 숫자 강조 띠("10년", "200명").
  값은 사장님이 말한 사실값만 들어온다는 전제라, `has_items`가 거짓이면
  부품 전체를 렌더하지 않는다(빈 띠 없음). 제목은 선택(없으면 `aria-label`).
  `intro--stats` 안의 격자(`.s-stats`)와 이름이 겹쳐서 섹션 클래스는
  `s-band s-stats--band`로 했다(충돌 회피, README에 기록).
- 두 파일 다 이중 중괄호만, 스크립트·아이프레임·폼·`http:` 없음.
  렌더러의 `_SafeText` 감싸기와 같은 조건으로 직접 렌더해 확인했다:
  이스케이프 유지, 빈 stats-band는 빈 문자열, 아이콘 SVG 2개 정상.
- 변수 계약은 `templates/README.md` §3·§4에 적었다(표 2행 + 파생값 2항 추가).
  렌더러가 붙기 전까지 6종 샘플 렌더에는 포함하지 않는다.

## 3. 전후 비교 (390x844, `docs/product/reviews/polish/`)

렌더는 `app.services.site_render.render_site` 호출만 썼다(렌더러 코드 변경 없음).
파일: `before-<업종>-390x844.png` 6장(작업 시작 시점),
`after-<업종>-390x844.png` 6장(작업 끝 시점).
나타나기는 움직임이라 고정 캡처에 안 담겨서, 후 캡처는 움직임 줄이기(rest 상태)로
찍고 나타내기는 따로 살폈다: 일반 창에서 스크롤하면 섹션 불투명도가 0 → 1로
올라가고, 줄이기 설정에서는 전부 1로 보인다.

- 공통: 제목이 커져서 첫눈에 들어오고, 섹션마다 밑줄 장식이 달라져서 리듬이 생겼다.
  띠가 번갈아 깔려서 "글만 죽 늘어선" 느낌이 줄었다. 카드·가격표에 그림자가 생겼다.
- pension(겹침형): 덮개가 위는 옅고 아래는 짙어서 예시 그림 위 흰 제목이 읽힌다.
  첫 화면이 화면의 약 70%라 아래 내용이 살짝 보여 스크롤이 유도된다.
- cafe(옆 배치): 첫 화면이 세로 가운데로 와서 빈자리가 안정적으로 보인다.
  사진첩 예시 그림 2장이 띠 안에서 나란히 보인다.
- restaurant·academy(stats 있음): 숫자 카드에 그림자+모서리 토큰이 탔다.
- salon(글자만 첫 화면): 70% 높이 + 가운데 정렬이라 휑하지 않다.
- workshop(tabs): 탭·카드 구조 그대로, 밑줄 장식(상품 56px)만 길어졌다.

## 4. 판단 (덜어낸 것)

- 띠를 전체 너비로 깔되 표시 구조는 안 바꿨다. 구조를 바꾸면 렌더러의 문자열
  갈아끼우기(hero 빈 사진, 사진첩 예시)와 공개 방식 `:has` 규칙이 깨질 수 있어서다.
- 제목 장식을 토큰(모서리·액센트)에 묶었다. 3안이 팔레트·글꼴·밀도·모서리를
  바꾸면 장식도 따라가서 안마다 비슷해지지 않게 했다.
- 나타내기는 `view()` 대응 곳에서만. 대응하지 않는 곳·인쇄·줄이기
  설정에서는 기존과 같은 고정 화면이 나온다. 내용을 숨기는 방식이 아니라서
  구형 기기에서도 빈 화면이 되지 않는다.
