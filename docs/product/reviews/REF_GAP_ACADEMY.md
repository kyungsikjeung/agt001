# 학원 레퍼런스 수준 분석 보고서 (REF_GAP_ACADEMY)

- 대상 레퍼런스: 로봇·코딩 학원 사이트 1곳 (아임웹 기반 제작, 추정)
- 우리 대상: 학원 미리보기 `static/compare/academy-v1~v3.html` + 부품·렌더러
- 날짜: 2026-09-27
- 규칙: 레퍼런스의 문구·이미지·코드는 베끼지 않음. 수준·구조·기법만 분석. 추측은 "추정"이라고 표시.

## 1. 레퍼런스 분석 (수준·구조·기법만)

### 1-1. 섹션 순서 (위에서 아래로)

| 순서 | 구역 | 하는 일 |
|---|---|---|
| 1 | 상단 메뉴 | 로고 + 메뉴 5개(소개·과정·캠퍼스·공지·문의) + 전화 상담 버튼 |
| 2 | 첫 화면 | 큰 주장 문장 2~3줄 + 짧은 설명 + 큰 사진 1장 |
| 3 | 공감 질문 | 학부모 고민 5개를 질문 카드로 나열 + 사진 |
| 4 | 교육 철학 | 핵심 가치 3개를 나열 (각각 제목+짧은 설명) |
| 5 | 브랜드 설명 | 머리글자 3개로 뜻풀이 (각각 제목+설명) |
| 6 | 과정 소개 | 단계별 과정 이름 + 설명 그림 여러 장 |
| 7 | 후기 | 학부모 후기 4개 카드 (별점 그림+긴 글+작성자) + 외부 후기 링크 |
| 8 | 마지막 상담 띠 | 짧은 권유 문장 + 버튼 2개(상담 예약·과정 보기) |
| 9 | 떠다니는 버튼 | 화면 하단 고정 "상담 안내·무료 체험" (휴대폰에서 항상 보임, 추정) |
| 10 | 바닥글 | 지점 3곳 주소·등록번호·수강료 자료 링크·저작권 표시 |

### 1-2. 첫 화면 구성

| 항목 | 내용 |
|---|---|
| 배치 | 글(왼쪽) + 사진(오른쪽) 또는 글 위·사진 아래. 글자가 먼저 읽힘 |
| 글자 단계 | 큰 제목(아주 크게·굵게) → 짧은 설명(보통) → 버튼 순 (크기 3단계, 추정) |
| 버튼 | 색이 채워진 큰 버튼 1개 + 보조 버튼. 전화 걸기 연결 |
| 사진 | 아이 활동 사진 같은 큰 이미지. 휴대폰용 별도 사진 있음 (추정) |

### 1-3. 글꼴·색 체계

| 항목 | 내용 |
|---|---|
| 글꼴 | 한글 고딕(Pretendard 계열) + 영문 제목용 글꼴 병행 (HTML에서 확인) |
| 메뉴 글자 | 19px·굵게 (HTML에서 확인) |
| 색 | 하늘색 계열 주색(`#44c5d6`, HTML theme-color에서 확인) + 어두운 글자 + 흰 바탕. 버튼에 올리면 밝아지는 효과 (HTML에서 확인) |
| 너비 | PC 본문 최대 약 1284px (HTML에서 확인). 우리(720px)보다 넓음 |

### 1-4. 사진·일러스트 사용 방식

| 항목 | 내용 |
|---|---|
| 비율·위치 | 구역마다 큰 사진 1장 이상. 글과 사진을 번갈아 배치 |
| 종류 | 실사진 중심 + 설명용 그림(과정·가치 설명). 장식용 작은 아이콘도 있음 (추정) |
| 휴대폰 | PC와 다른 세로형 사진으로 교체하는 자리 있음 (HTML에 mobile background 표시 있음) |

### 1-5. 부품 종류 (카드·배너 등)

| 부품 | 모양 |
|---|---|
| 질문 카드 | 이모지+질문 1줄 묶음 5개 |
| 가치 3칸 | 제목+설명 3개를 가로로並べ (PC) |
| 과정 그림 | 단계별 설명 그림을 세로로 길게 나열 |
| 후기 카드 | 긴 글 + 작성자 표시, 옆으로 미는 형태 (추정) |
| 상담 띠 | 바탕색 있는 가로 띠 + 버튼 2개 |
| 지점 안내 | 지점별 주소·번호를 바닥글에 나열 |

### 1-6. 신뢰 요소

| 요소 | 있음/없음 |
|---|---|
| 원장 인사말·학원 성과·이야기 | 있음 (메뉴에 별도 페이지) |

| 수상·실적 숫자 | 본문 첫 화면에 숫자(예: 수상 N회)는 없음. 성과는 별도 페이지 (추정) |
| 등록번호·수강료 공개 | 있음 (지점별 등록번호 + 수강료 자료 링크) |

| 항목 | 내용 |
|---|---|

| 움직임 | 스크롤하면 내용이 아래에서 올라오는 효과(AOS 라이브러리, 0.7초·1회, HTML에서 확인). 메뉴 펼침·버튼 떠오름은 CSS 전환 (추정) |

## 2. 우리 학원 시안 현황

### 2-1. 지금 나오는 섹션·부품 (academy-v1 기준, v2·v3은 변형)

| 순서 | 우리 섹션 (부품 이름) | 내용 |
|---|---|---|
| 1 | hero `text-only` | 가게 이름 크게 + 한 줄 소개 + 영업·위치 정보 + 상담 신청 버튼. 사진 있으면 `photo-overlay`·`photo-side`로 바뀜 |
| 2 | offerings `list-price` | 반 목록 ("반 구성"). 이름만, 가격은 빈칸 |
| 3 | intro `stats` | 소개 글 + 숫자 4칸 (숫자는 사장님이 말해야 들어감) |
| 4 | gallery `grid` | 사진첩. 사진 없으면 예시 그림 2장 + "사장님 사진으로 바뀌어요" 안내 |
| 5 | around `map-list` | 주소 + 오시는 길 |
| 6 | contact `call-first` | 전화·영업시간·주소 표 |
| 7 | cta `call-sms` | 예약·문의 버튼 띠 (전화 있으면 자동 제거됨) |
| 8 | booking `form` | 상담 예약 신청 양식 (날짜·시간·인원·연락처) |
| 9 | contact `form` | 문의 보내기 양식 |
| 10 | reviews `slot-only` | "후기가 모이면 여기에 표시됩니다" 한 줄 (후기 내용 없음) |

- v2 차이: 첫 화면 `photo-side` + 반 목록 `photo-grid` (사진 카드형)
- v3 차이: 반 목록 `tabs` (눌러서 바뀌는 과정 탭, CSS만) + 소개를 앞으로
- 학원 컨셉: 남색 바탕 느낌·또렷한 고딕·각진 모서리·반 안내를 앞에 (`design_concept.py`, 추정 아님·파일 확인)

## 4. 결론

### (a) 몇 %까지 가능한지 (추정)

- **우리 구조로 레퍼런스 수준의 약 65~70%까지 가능 (추정).**
- 근거: 배치는 단순한 글+사진 쌓기와 3칸 카드라 우리 부품으로 재현 가능. 글꼴·색·버튼·상담 양식·휴대폰 쌓기는 토큰+CSS로 커버됨. 스크립트 효과는 CSS로 비슷하게 낼 수 있음.
- 나머지 약 30~35%는 사진·후기·실적·강사 같은 "사장님 실제 자료"와 "페이지 여러 장 나누기"라서 구조상·정보상 못 따라감 (추정).

### (b) 필요한 새 부품 목록

| 이름 | 들어갈 내용 | 휴대폰 배치 |
|---|---|---|
| `worry--list` | 학부모 고민 질문 4~6개 (이모지 없이 글머리 점+질문) | 세로 1열 쌓기 |
| `values--3col` | 가치 3개 (제목+짧은 설명). 기존 `features--icons`로 임시 대체 가능 | 1열 쌓기 (PC에서 3칸) |
| `steps--vertical` | 과정 단계 (번호+단계 이름+설명 1~2줄) | 세로 타임라인 1열 |
| `staff--cards` | 강사 사진+이름+맡은 반+한 줄 소개 | 1열 쌓기 (PC에서 3칸) |
| `cta--sticky` | 하단 고정 상담 버튼 1~2개 (CSS sticky만) | 하단 고정 가로 꽉참 |

### (c) 사장님께 받아야 할 자료

1. 강사 사진 + 이름 + 맡은 반 (없으면 `staff` 부품 빈칸)
2. 실적 숫자 (수상·졸업생·연차 등, 지어내지 않음. 없으면 숫자칸 숨김)
3. 학부모 후기 3~5개 (긴 글 + 작성자 표기 허락 + 외부 후기 링크)
4. 반 구성·단계별 과정 설명 (단계 이름+설명+대상 나이)
5. 실사진 5장 이상 (교실·수업·아이 활동. 얼굴 공개 동의 포함)
6. 지점별 주소·전화·등록번호·수강료표 (바닥글·문의용)
7. 공감 질문 문장 (학부모가 자주 묻는 고민 5개)

### (d) 할 일 순서

**1일 안에 (코드만, 자료 없이):**

1. `values--3col` 대용으로 `features--icons`를 학원 기본 조합에 포함
2. `cta--sticky` (CSS sticky 하단 상담 버튼) 추가
3. 학원 PC 너비 완화 (720px → 넓은 화면에서 3칸 카드가 시원하게)
4. CSS 스크롤 나타내기가 레퍼런스와 비슷하게 보이는지 육안 확인

**3일 안에 (자료 받으면서):**

1. `worry--list` + `steps--vertical` 부품 추가
2. `staff--cards` 부품 추가 + 사장님 강사 자료 입력
3. 후기·실적 숫자 입력되면 `reviews--list`·`stats--band`로 교체
4. 실사진 오면 예시 그림 자리 교체 + 휴대폰용 세로 사진 지정

## 5. 참고: 카페 결론("배치는 단순 격자, 품질은 사진·정보에서")이 학원에도 맞는지

- **대체로 맞다. 다만 학원은 "글의 설득 순서" 비중이 카페보다 크다.**
- 맞는 점: 레퍼런스의 배치 자체는 글+사진 쌓기와 3칸 카드라 단순함. 사진(수업 장면)·실제 후기·등록번호 같은 실제 자료가 품질을 결정함. 우리 예시 그림만으로는 못 따라감.
- 다른 점: 카페는 상품 사진·가격이 핵심이지만, 학원은 "학부모 고민 → 교육 철학 → 과정 단계 → 후기 → 상담"이라는 글의 순서가 핵심 설득 수단임. 그래서 카페보다 새 글 부품(`worry`·`values`·`steps`)이 더 필요함. 사진보다 "사장님 말(철학·고민 답·실적)"이 병목임 (추정).
