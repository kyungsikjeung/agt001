# 구성 인터뷰 · 실시간 대화 미리보기 계약 (2026-10-03)

> 대표 요청(10/3): 음성 버튼을 누르면 "어떤 사이트를 만들고 싶으세요?"를 소리로 묻고, 업종을 알면 그 업종에 들어갈 수 있는
> 화면 부품(첫 화면·메뉴·사진·지도…)을 하나씩 쉬운 말로 물어 확정하고, 확정할 때마다 화면이 바로 생기게 한다.
> 모바일·PC를 함께 본다. 기존 화면은 백업한다.

## 1. 결정

| # | 결정 | 이유 |
|---|---|---|
| C-1 | 질문 하나 = 부품 하나. 선택지는 렌더러에 있는 부품 종류(`templates/sections/<type>--<variant>`)에 1:1로 대응 | AI가 HTML을 새로 쓰지 않는다(보안·품질 유지). 시험으로 모든 선택지가 실제 부품인지 확인 |
| C-2 | 부품 후보는 업종 원형 청사진(`templates/blueprints`)의 3안 구역을 합친 것. 첫 화면 → 1안 순서 → 나머지 | 원형마다 이미 손님 동선을 정해 둔 표를 그대로 쓴다 |
| C-3 | 구성 질문은 질문 한도(D20) 밖으로 센다. 선택지마다 "알아서 해주세요"(=추천 모양) | 질문 수 목표(평균 3회)와 충돌하지 않게. 대표 확인 전 추천안 |
| C-4 | 첫 화면 영상은 1차 제외. "영상"이라고 하면 첫 화면은 사진 크게 + 바로 아래 영상 칸(video--card) | 렌더러에 배경 영상 첫 화면이 없다 |
| C-5 | 빼면 손님이 행동을 못 하는 부품(첫 화면·메뉴·문의·객실·수업)은 빼기 선택지가 없다. 모양이 하나뿐이면 묻지 않고 넣는다 | "객실을 넣을까요? [넣기]" 같은 무의미한 질문을 없앤다 |
| C-6 | 부품을 정하면 그 부품의 사실을 바로 잇는다: 첫 화면→가게 이름, 메뉴→메뉴·가격, 지도→위치, 문의→연락 방법(전화 버튼이면 번호) | 정한 부품이 곧바로 채워져 보인다 |
| C-7 | 못 알아들으면 한 번 다시 묻고, 그다음엔 추천 모양으로 두고 알린다 | 손 안 쓰는 대화가 멈추지 않게 |
| C-8 | 대화는 채팅방 기록에도 남고, 끝나면 기존 요약·승인 흐름(chat_flow `_gate_or_summary`)으로 넘긴다 | 시안 3안·공개는 채팅방에서 그대로 이어 간다 |

## 2. 서버

- `app/services/compose.py`
  - `live_turn(card, text)` → `{reply, question, done, phase, last}`. phase: `kind`(업종 묻기) · `compose`(부품) · `fact`(부품의 사실) · `engine`(남은 엔진 질문)
  - 상태는 `card["compose"] = {steps, chosen{id: variant}, skipped[], pending, facts[], retry, last, order[]}`
  - `preview_spec(card)` / `preview_html(card)`: 정한 부품만 청사진 순서로 쌓아 `site_data.resolve` → `site_render.render_site`
- `app/api/live.py` (방장만, 아니면 403)
  - `POST /api/rooms/{room_id}/live/turn {"text"}` → `{reply, question, question_text, speech, options[], phase, done, last, components[]}`. 빈 글이면 지금 질문만(진전 없음). 질문을 다 마친 방(`GATHERING` 밖)은 409
  - `GET /api/rooms/{room_id}/live/preview` → `{html|null, components[], last}`
