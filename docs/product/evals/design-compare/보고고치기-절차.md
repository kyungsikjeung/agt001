# 보고 고치기 절차 (P3-7, D42-3)

스크린샷 → 지적(사람 입력) → 명세 수정 → 전후 점수 비교. 하네스: `evals/run_report_fix.py`.
지적은 사람이 넣고, 명세 패치는 `design_concept.adjust()`의 규칙 경로
(`_keyword_adjust`)만 직접 쓴다 — `adjust()` 본체는 AI를 먼저 부르므로 쓰지 않는다
(AI 호출 없음, 비용 0원). 전후 점수는 `run_site_quality` 6요소 그대로.

## 체크리스트

- [ ] 1. 스크린샷 보기: `.venv/bin/python -m evals.run_site_quality --out <폴더>`로
  해당 업종 쪽을 만든 뒤 `<업종>-full-v1-fold.png`(첫 화면)를 사람 눈으로 본다.
- [ ] 2. 지적 입력:‐ 본 것을 한 문장으로 `--note "…"` (또는 `--note-file`)에 넣는다.
  규칙 대응 키워드: 따뜻·고급·세련·귀엽·차분·화사·넉넉·촘촘·둥글·각지·사진 먼저·메뉴 먼저·소개 먼저.
- [ ] 3. 명세 패치: 하네스가 `_keyword_adjust`로 컨셉만 바꾸고 같은 변형(v1)에 다시 그린다.
  대응 키워드가 없으면 하네스가 멈추고 다른 문장을 요구한다 (지어내지 않음).
- [ ] 4. 전후 비교: 수정 전후 6요소(제목 대비·여백 리듬·색·카드버튼·첫 화면 행동) 표를 확인하고,
  바뀐 값(palette·font·density·radius·lead·mood)을 기록한다.

실행: `.venv/bin/python -m evals.run_report_fix --industry cafe --note "차분한 느낌으로 바꿔줘"`

## 시범 1회 (cafe, 2026-09-27)

- 지적(사람 입력): 차분한 느낌으로 바꿔줘
- 명세 패치: `_keyword_adjust` 규칙 경로만. 답: 차분한 느낌으로 바꿨어요.
- 바뀐 값: palette coffee→sage, mood ['포근한', '여유로운', '향긋한']→['차분한', '포근한', '여유로운']
- 걸린 시간 1.1초, 비용 0원. 같은 v1에 명세만 교체.

| 구분 | 6요소 | 누를 것 |
|---|---|---|
| 수정 전 | 제목 대비O·여백 리듬O·색O·카드·버튼O·첫 화면 행동O (5/5) | O |
| 수정 후 | 제목 대비O·여백 리듬O·색O·카드·버튼O·첫 화면 행동O (5/5) | O |

| 구분 | 제목비율 | 여백종류 | 첫화면그림 | 색수 | 버튼모양 | 첫화면행동 |
|---|---|---|---|---|---|---|
| 수정 전 | 2.75 O | 1 O | 0.10 | 1 O | O | 1 O |
| 수정 후 | 2.75 O | 1 O | 0.10 | 0 O | O | 1 O |

판독: 6요소 통과는 전후 동일(5/5). 색수만 1→0으로 좋아졌고, 그 외 원값은 그대로 —
규칙 패치가 점수를 깨지 않음을 확인한 수준이며, 사람 눈(스크린샷 대조)이 최종 판정이다.
