# T2 추출 평가: 녹화 재생 채점 (2026-10-01)

실제 AI를 다시 부르지 않고, 9/26 1~3차에서 **AI가 실제로 낸 값**(실패 사례 표의 "실제" 칸)을
지금 엔진(`apply_updates`)에 다시 넣어 채점했다. 통과했던 케이스는 기대 값을 한 줄 값으로 넣었다.
그래서 이 숫자는 "같은 AI 답이 오면 지금 엔진이 몇 점을 받는가"이고, 새 실측(NIM 키 필요)은 아직이다.

## 결과

| 녹화 | 9/26 당시 | 오늘 고치기 전 엔진 | 고친 뒤 | 지어낸 값 |
|---|---|---|---|---|
| 1차 | 77.3% | 83.4% | **93.3%** | 0 |
| 2차 | 90.2% | 84.0% | **95.7%** | 0 |
| 3차 | 87.1% | 82.2% | **98.8%** | 0 |

"고치기 전 엔진"이 9/26보다 낮은 것은 그 뒤에 들어간 영업시간 저장 검사(W1) 때문이다.
말로 한 시각("오후 세 시", "열 시")을 숫자로 못 읽어 모두 "영업시간 숫자가 없어요"로 막았다.
다음 실측을 그대로 돌렸으면 시간 칸 10개 남짓이 더 틀렸을 것이다.

## 고친 것

1. **말로 한 영업시간 저장** (`validate.check_hours`, `numbers.native_hours_to_digits`): "세 시" → "3시"로 읽고 검사한다. "한 시간"은 시각으로 보지 않는다.
2. **숫자 글자 없는 시각의 근거 판정** (`prd_engine.grounded`): "열 시"처럼 한 글자 낱말만 있는 값을 근거 없음으로 버리던 것.
3. **추출 보충 규칙** (`prd_engine.backfill_from_text`): AI가 되풀이해 놓친 말 모양만 사장님 말 조각 그대로 더한다. AI 값은 바꾸지 않는다.
   - "강남에서 미용실 빛나헤어 해요" → 위치·가게 이름, "위치는 홍대예요", "이름은 작은숲이라고"
   - "직장인들이 많이 와요", "손님은 동네 주민들이랑 학생들이에요", "초보도 된다" → 대상 손님
   - "파마 잘해요", "염색이랑 클리닉이 주력", "파닉스부터 가르쳐요", 업종 "영어 학원"의 과목 → 품목
   - "칼국수 8천원, 수육 2만원" → 품목·가격 짝
   - "매주 월요일 쉬고" → AI가 낸 영업시간 앞에 "월요일 휴무"
   - "예약 문의를 늘리고 싶고" → 목적, "전화로 받아요" → 연락 방법, "공일공에 0000에 3456번" → 전화
   - "커피요.", "네일이요." → 업종
4. **추출 프롬프트**: 휴무일, 대상·품목 말 모양, 긴 메시지 다시 보기를 한 줄씩 더했다.
5. **기대 값 조정 1건** (e005): 가게 이름 "바다정원"만 내도 맞게(원문 "바다정원 펜션 해요"에서 둘 다 옳다), 특징은 "보여/보이는" 어미 차이를 받게 "바다가 보".

보충 규칙만 단독으로 돌려도(AI 답 없음) 60개 모두 must_not·빈 기대를 어기지 않는다(`tests/engine/test_extract_backfill.py`).

## 남은 것

- 실제 AI로 다시 측정(NIM 키 필요): `python -m evals.run_extraction --out docs/product/evals/extraction-<날짜>.md`
- e056 업종 "영어 교습소"를 "영어 학원"으로 바꿔 적는 것, e045 사투리 수업 시간은 AI 쪽 문제로 남는다.
