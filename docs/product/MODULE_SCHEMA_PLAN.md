# 기능 모듈 = 내용 유형표 계획 (MODULE_SCHEMA_PLAN)

> 2026-10-03 (KST). 대표 질문 4개에 대한 답과 계획. 계획 Claude, 구현 OpenCode(물결 단위).
> ① 숙박 달력·빈방(정규화가 되나, 호텔 말고 어디에 쓰나) ② 주변 안내(도보 10분·10km 이내, 사장님이 넣는 장소)
> ③ 엔진이 "분류된 것에 어떤 부품이 필요한지" 모른다(카페 메뉴: 분류 → 사진·가격·결제 버튼) ④ 사장님이 넣은 값을 관리자 화면에서도 관리

## 0. 사업 구조 (대표 확인)
- 사장님은 BaaS(백엔드 서비스)를 따로 몰라도 된다. **정해진 돈 → 빌더 + 호스팅 + 도메인**, **기능을 하나 더할 때마다 추가 요금**.
- 그러려면 기능 하나 = **모듈 하나**가 켜고 끄고·값을 매길 수 있는 단위여야 한다. 지금은 기능 지식이 코드 곳곳(item_plan의 업종표, card_data의 낱말표, site_data의 bind별 함수, 청사진 JSON, 빌더 SectionPanel의 bind별 분기)에 흩어져 있다.

## 1. 왜 엔진이 부품을 못 고르나 (③의 원인)
| 지금 | 문제 |
|---|---|
| `item_plan.KIND_BY_INDUSTRY` 업종 → 항목 종류 고정 | 업종표 밖(새 종류)은 'menu'로 떨어진다 |
| `item_plan.FIELDS` 종류별 칸 목록이 **이름만** | 칸의 형식(돈·사진·기간·인원)과 "손님이 무엇을 하려고 보나"가 없다 |
| `card_data._classify` 분류 낱말표가 카페·미용실만 | 논카페인·티·에이드·브런치 등은 '메뉴'로 뭉친다. 분류 이름도 사장님 말보다 낱말표가 먼저 |
| 부품 선택은 청사진에 미리 박힘 | "분류가 있으니 분류 탭, 결제가 켜졌으니 담기·결제 버튼, 사진 칸이 있으니 사진 카드"를 **내용에서 끌어내지** 않는다 |
| 빌더 고치기 칸은 bind별 수작업 | 새 종류마다 화면을 새로 짜야 한다(오늘 선생님 칸처럼) |

## 2. 해법: 내용 유형표 (`app/data/content_types.json`)
한 유형 = 손님이 보는 한 묶음. 엔진·부품·빌더 고치기 칸·관리자 화면·DB가 **모두 이 표 하나를 읽는다.**

```json
{"menu_item": {
   "label": "메뉴", "group_by": "category",
   "fields": {"name": "text20", "price": "money", "photo": "photo", "desc": "text80",
              "category": "choice", "options": "list(text12)", "soldout": "bool"},
   "visitor_needs": ["분류로 빨리 찾기", "사진으로 고르기", "가격 보기", "담아서 결제"],
   "components": {"group": "category-tabs", "item": "photo-price-card", "detail": "item-sheet",
                  "action": {"info": null, "order": "cart-button", "pay": "pay-button"}},
   "ask_if_missing": {"price": "가격을 알려 주세요", "category": "메뉴를 어떻게 나눌까요?"}},
 "room": {"label": "객실", "unit": "night", "fields": {"name": "text20", "photos": "photos", "capacity": "int",
          "base_price": "money", "rates": "rate_rules", "count": "int"},
   "components": {"search": "date-range-guests", "list": "vacancy-list", "item": "room-card", "action": {"book": "book-pay"}}},
 "teacher": {"label": "선생님", "fields": {...}, "components": {"list": "staff-cards", "detail": "staff-popover"}},
 "place_nearby": {"label": "주변", "fields": {"name": "text20", "category": "choice", "lat": "geo", "lng": "geo",
                  "note": "text40"}, "derived": {"distance": "from_shop"},
   "components": {"list": "around-distance-list", "map": "around-map"}}}
```
- **엔진**: 카드 → 유형(LLM이 고르고 표로 검증, KIND_INFER처럼) → 칸이 비었으면 `ask_if_missing` 질문 → `components`로 부품 고르기 → 표에 없는 부품은 D44 '못 담은 요구'로.
- **분류**: 사장님이 말한 분류가 먼저, 없으면 LLM이 항목 이름으로 분류 제안(커피·논카페인·티·에이드·디저트·브런치) → 사장님 확인 한 번. 낱말표는 LLM 실패 때만.
- **빌더 고치기 칸**: `fields`의 형식(text20·money·photo·choice·rate_rules…)으로 **자동 폼**. bind별 수작업 패널을 하나씩 걷어낸다.
- **관리자 화면(④)**: 같은 표로 가게별 유형 데이터를 목록·고치기(누가 언제 바꿨는지 admin_audit에 기록, 전화번호 가림 그대로).
- **요금(0)**: 모듈 = 유형 + 행동(`action`). 예: 메뉴 보기는 기본, `order`·`pay`는 추가 모듈. 켜짐 상태는 shop_settings.

## 3. 숙박 달력·빈방 (①) — 정규화된다
이미 있는 예약 엔진(0016)이 뼈대다: `booking_specs`(가게별 명세 JSON, 버전), `booking_blocks`(막은 기간), `bookings`(자원·시작·끝, **겹침은 DB 배제 제약이 막음**).
| 표 | 넣는 사람 | 칸 |
|---|---|---|
| 자원(객실) | 사장님(빌더·사장님 화면) | 이름, 사진, 기준·최대 인원, 같은 방 개수, 기본가(1박), 단위(박·시간·일·회차) |
| 요금 규칙 | 사장님 | 기간 또는 요일(금·토), 시즌(성수기), 1박 가격 또는 +금액, 최소 박수 |
| 막은 날 | 사장님 | 자원(또는 가게 전체), 기간, 이유 |
| 예약 | 손님(사이트·채팅)·사장님(전화 받은 것) | 자원, 체크인~체크아웃, 인원, 상태(요청·확정·거절), 결제 |
- **빈방 = 기간 안에 겹치는 예약·막은 날이 없고 인원이 맞는 자원**, **가격 = 박마다 요금 규칙(없으면 기본가)의 합**. 계산은 서버 한 곳(availability).
- 손님 화면: 참고 이미지처럼 **두 달 달력에서 체크인·체크아웃 고르기 + 인원** → 빈방 목록(사진·인원·총액·'예약하기') → 결제(포트원 테스트 채널) 또는 신청.
- **호텔 말고 쓰이는 곳**(단위만 바뀜): 펜션·캠핑장·글램핑 자리(박), 파티룸·스터디룸·연습실·회의실·촬영 스튜디오(시간), 한복·캠핑 장비·카메라 대여(일), 공방 원데이 클래스·학원 체험 수업 좌석(회차·정원), 미용실 디자이너·네일 자리(시간 칸), 골프 연습 타석, 반려견 호텔(박).

## 4. 주변 안내 (②)
- 사장님이 빌더 '주변' 칸에서 **장소 검색**(카카오 지도 JS SDK의 장소 검색, 이미 등록한 JS 키·도메인) → 이름·분류(관광지·맛집·카페·편의점·역·버스)·좌표 저장, 한 줄 메모.
- 거리는 가게 좌표(주소 검색에서 이미 받음)와의 직선거리로 자동: 1km 안 **도보 N분**(분당 67m, 올림), 그 밖 **차로 N분**(시속 30km 가정) 또는 **N km**. "10km 이내" 묶음 머리글.
- 부품: 거리 목록(분류 아이콘·이름·도보 N분) + 지도 표시. 공개본 스크립트 없이 목록, 지도는 기존 예외 SDK 한 개.

## 5. 순서 (추천)
1. **유형표 W1**: `content_types.json` + 읽기 모듈 + 메뉴(menu_item) 하나로 엔진·분류 제안·부품 선택을 표 기반으로. 카페 '분류 탭 → 사진·가격 카드 → 담기·결제' 흐름이 내용에서 나오게.
2. **숙박 W2**: room 유형 + 요금 규칙·달력 검색·빈방 목록·예약(0016 위에). 단위 '박'.
3. **주변 W3**: place_nearby 유형 + 장소 검색·거리 계산·부품.
4. **자동 고치기 칸·관리자 W4**: fields 형식으로 빌더 폼·관리자 목록 자동 생성, bind별 수작업 패널 정리.
5. 이후 단위 '시간·일·회차'로 넓혀 위 3장의 다른 업종.
