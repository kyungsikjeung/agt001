# 기능 사례집 (입구 게이트 참조용 초안)

> 작성일: 2026-09-26 / 상위: [INTAKE_GATE_DESIGN.md](INTAKE_GATE_DESIGN.md) §4
> 기계용 원본: `app/data/feature_catalog.json`(기능 42개), `app/data/intake_profiles.json`(문의 종류 프로필)
> 성격: 입구 게이트가 기능 요구를 판정할 때 참조하는 첫 자료. 확정 사실은 여기서가 아니라 요구사항 카드에서 읽는다.

## 1. 판정 기준

베타 조건 3가지에 맞춘다: **정적 사이트 + 부품**, **결제 없음**(D13), **사이트 방문자 데이터 저장 없음**(UQ-4).

| 판정 | 뜻 | 게이트 동작 |
|---|---|---|
| 바로 가능 | 부품으로 지금 만들 수 있다 | 카드에 넣음 |
| 대체안으로 가능 | 그대로는 안 되지만 대신할 방법이 있다 | 대체안을 제시하고 고르게 함 |
| 사장님 준비 필요 | 사장님이 준비(채널 개설·도메인 구매 등)하면 된다 | 할 일을 쉬운 말로 안내 + 준비 전에는 대체안으로 |
| 베타 범위 밖 | 베타에서 못 한다 | 솔직히 알리고 "나중 목록"에 기록 |

## 2. 기능별 판정표

### 연락·문의

|---|---|---|---|---|

| 사이트 문의 양식 → 사장님 카톡 전달 | 베타 범위 밖 | 베타 뒤 검토(우리 앱 로그인·동의 방식) | 베타 뒤 안내 예정 | 채널 채팅 버튼, 전화·문자 버튼 |
| 카카오 알림톡 발송 | 베타 범위 밖(D6 보류) | 비즈니스 채널·발송 대행사·템플릿 심사·건당 과금 | 베타 뒤 안내 예정 | 채널 채팅 버튼 |

| 채팅 상담 위젯(실시간 채팅창) | 대체안으로 가능 | 사이트 내 채팅창은 외부 스크립트라 규격에 안 맞음 | 외부 서비스 계정(쓰려면, 베타 뒤) | 채널 채팅 버튼, 전화·문자 버튼 |

## 3. 카카오톡 문의 3가지 방법(§4 예시 그대로)

| 방법 | 판정 | 조건 |
|---|---|---|
| 카카오톡 채널 1:1 채팅 버튼 | 사장님 준비 필요(무료) | 사장님이 카카오톡 채널을 만들고 주소를 알려주면 된다. 키 불필요 |
| 사이트 문의 양식 → 사장님 카카오톡 "나에게 보내기" | 베타 범위 밖(검토) | 우리 카카오 앱으로 사장님이 한 번 로그인·동의하면 가능. 다만 문의 양식 저장은 베타 제외 결정(USER_DB_PLAN UQ-4)과 부딪힌다 |
| 카카오 알림톡 | 베타 범위 밖 | 비즈니스 채널·발송 대행사·템플릿 심사·건당 과금(D6 보류) |

## 4. 문의 종류 프로필 요약

`app/data/intake_profiles.json`에 정의. 가게·매장은 `app/services/prd_schema.py` 6업종 표를 그대로 쓴다.

| 종류 | 필수 칸 | 기본 섹션 |
|---|---|---|
| 개인·전문가 | 업종, 활동명·이름, 레슨·서비스 내용, 대상, 연락 방법, 사이트 목적 | 소개, 경력·작품, 레슨·서비스 안내, 일정, 문의 |
| 단체·모임 | 업종, 단체 이름, 활동 내용, 함께할 사람, 연락 방법, 사이트 목적 | 단체 소개, 활동 안내, 일정·공지, 가입·문의 |
| 기능 중심 웹서비스 | 업종, 서비스 이름, 서비스 목적, 필요한 기능, 연락 방법 | 서비스 소개, 기능 안내, 이용 안내, 문의(기능은 사례집 판정) |

거절 신호(사칭·피싱·불법 도박·성인 등 7종)와 모호할 때 묻는 질문 1개("어떤 사이트를 만들고 싶으세요?" — 가게·매장 / 개인·전문가 / 단체·모임 / 기능이 있는 웹서비스)도 같은 파일에 있다.
