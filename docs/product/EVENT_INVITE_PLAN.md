# 초대·기념 사이트 (청첩장) 계획 (EVENT_INVITE_PLAN)

> 2026-10-02 (KST). 대표 지시: "결혼 청첩장"이라고 했더니 '가게·개인·단체·웹서비스' 넷 중 고르라는 질문이 나왔다.
> 표에 맞추지 말고, 그 사이트에 무엇이 필요한지 생각해서 **있는 부품은 쓰고 없는 부품은 부품 빌더에 요청**해야 한다.

## 원인
`industry_of()`가 6업종·프로필(individual·group·webservice) 별칭 어디에도 '청첩장'이 없어 `other` → `next_question()` 1-1이
`site_kind`(4지선다)를 한 번 묻는다(`app/services/prd_engine.py`, 데이터 `app/data/intake_profiles.json` `ambiguous`).

## 예시 사진 (대표 지시 10/2: 새 요구면 Gemini로 사진을 만들고 태그를 달아 보여 줘야 의미가 있다)
6업종 밖(other·개인·단체·웹서비스)은 기본 그림이 카페 판화라 청첩장에 카페 그림이 나왔다.
→ 사진 창고(art_lib)에 **장면 사진**: 종류 낱말(예: 결혼청첩장)로 LLM이 장면 5개(태그·영어 설명, 첫 장 = 대표)를 정하고
Gemini로 만들어 `/art-lib/<태그>.webp`에 둔다(같은 종류는 다시 묻지 않고 재사용). 만들어지면 시안을 다시 그린다.
첫 화면·사진첩은 사장님 사진 → AI 예시 → 목업 → **장면 사진** → 기본 그림 순. 사람·얼굴·글자 없는 사물·장소만.
실측: 처음엔 '청첩장'을 종이 카드로 읽어 카드·봉투만 골랐다 → "사이트가 다루는 주제를 그려라"로 고쳐 반지·부케·예식 아치·피로연 테이블.

## 단계
1. ✅ 새 부품 3개 (`templates/sections/{event--date,family--contacts,gift--accounts}.mustache`, `templates/css/50-event-parts.css`, `site_render` 문맥·공개본 규칙·공용 스크립트, `tests/unit/test_event_parts.py`)
2. ✅ 초대·기념 원형 I + 질문 흐름: `intake_profiles.json` `event`(청첩장·결혼식·돌잔치·칠순·팔순·환갑·고희연·초대장) → 두 분 성함 → 날짜·시간 → (주차·식사·셔틀) → 장소. 청사진 `templates/blueprints/I.json` 3안(단정한 초대장·사진 이야기·날짜 먼저, 앱형으로 안 바꿈). 데이터 연결 `site_data`: greeting·event(한국어 날짜 읽기, 못 읽으면 예시 날짜)·family(두 분 성함을 신랑측·신부측으로, 번호 없으면 예시)·gift(빌더에서 넣기 전 예시 계좌). 첫 화면·사진첩은 장면 사진. `prd_engine.py`는 건드리지 않음(#16~#18과 겹침 방지)
   - ✅ 빌더에서 양가 연락처·계좌 넣기: `PUT /card` `event`(family·gift, 서버 검사: 전화 자리수·계좌 숫자 6~20·주민번호 거부, 틀리면 누구 칸인지 400), 고치기 칸 `EventEditor`(측마다 최대 4줄). 넣은 값이 예시를 대신하고 공개본에도 나간다. 인사말·날짜와 장소도 고치기 칸에서 바로
   - ✅ 참석 여부 받기: 부품 `rsvp--form`(측·이름·참석·인원·식사·연락처 선택·남길 말) → `POST /api/rsvp/{site_key}` → 문의 저장소에 '[참석 여부] 신부측 · 참석 · 2명 · 식사함'(알림·카톡·보관 30일 그대로). 미리보기 주소 허용 목록에 `/api/rsvp/`. 아래 고정 버튼 = 오시는 길 + 참석 여부
3. 방명록: 하객 글 저장(플랫폼 공용 DB, D31), 신랑·신부 삭제, 욕설 거르기, 최신순
4. 엔진 일반화: 모르는 업종이면 4지선다 대신 "필요한 내용" 추론 → 부품 대응 → 없는 부품은 요청 목록(D44, 관리자 화면). **PR #17·#18(질문 흐름) 합친 뒤**
