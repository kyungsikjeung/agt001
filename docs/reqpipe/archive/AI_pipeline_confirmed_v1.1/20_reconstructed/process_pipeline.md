## 루프백 원칙

- 계층 판정은 **규칙표 12케이스로 고정**. LLM 판정 금지
  (같은 결함에 매번 다른 계층으로 되돌아가면 프로세스가 아니라 복권이 됨)
- 핵심 두 규칙
  1. 같은 상위에서 파생된 하위 둘이 모순 → **상위가 원인**
  2. 동일 결함 2회 재발 → **한 계층 상위로 강제 승격** (없으면 코드 레벨에서 무한 순환)

## 질문 · 에스컬레이션

- Top-k = 3 + 추천안. 점수 = w1·영향도 + w2·불확실성 + w3·차단도 − w4·답변비용, MMR로 중복 제거
- 무응답 시 추천안을 가정(assumption)으로 채택하되 **safe/risky 등급 구분**.
  보안·법규·정합성은 자동 채택 금지, BLOCKED 유지
- 에스컬레이션 L0→L1→L2→L3 = 4h / 24h / 48h, 업무시간 기준 정지
- audience 축: internal(CLI 큐) / customer(카카오톡 링크). **customer 항목을 내부 큐에 노출 금지**

## 관통 원칙 (must_not 중 핵심)

- 코어에 도메인 어휘 하드코딩 금지 — 도메인은 프로파일 YAML로만 주입
- 도메인 판별을 LLM에 위임 금지 — CLI 인자로 명시
- descriptive(코드에서 읽은) 근거 단독 자동채택 금지 — 승인 문서만 A밴드
- 출처 없는 값이 산출물에 진입 금지 (인터뷰 답변도 evidence로 기록)
- 진행률 자기보고 금지 / 테스트 없이 TODO 완료 금지 / 사람 코드 덮어쓰기 금지
- 수락 미달 시 릴리스 생성 금지 / provisional 1건이라도 남으면 릴리스 금지
- 질문 순서에 난수 금지 (리플레이 재현성)
